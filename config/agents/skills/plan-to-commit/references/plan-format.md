# plan フォーマット

`plans/<slug>.md` はこのテンプレートに従う。見出しごとの意図は以下の通り。

- 「背景 / なぜ」「方針」は、そのままコミットメッセージ本文に転記される（`commit-handoff.md` 参照）。作業メモではなく、**意思決定の記録**として書くこと。
- 「ゴール」は実装完了の判定基準になる（フェーズ2の出口条件）。
- 「やらないこと」はスコープ外を明示し、過剰実装を防ぐ。
- 「変更計画」はフェーズ2で上から順にそのまま実行する手順になる。
- 「検証」はフェーズ2実装中・フェーズ4修正後に実際に回すコマンド。実行して通ったものだけがコミット本文に載る。
- 「リスク / ロールバック」は壊れうる箇所の事前見積もりで、フェーズ5でのコミット粒度判断にも使う。

## テンプレート

```markdown
# <一行タイトル: 何をするか>

## 背景 / なぜ
<今なにが問題か。この変更をしない場合に何が起きるか。コミット本文の「なぜ」になる部分>

## ゴール
- <達成できたと言える条件を箇条書きで。検証可能な形で>

## やらないこと
- <スコープ外。過剰実装を防ぐ>

## 方針
<採った設計と、他に検討して捨てた案があればその理由>

## 変更計画
1. `path/to/file.ts` — <何をどう変える>
2. ...

## 検証
- [ ] `<実行するコマンド>`
- [ ] <手動確認する内容>

## リスク / ロールバック
<壊れうる箇所と、戻し方>
```

## 記入例

```markdown
# CLIの --context-only フラグが値を無視するバグを直す

## 背景 / なぜ
`--context-only=false` を指定しても常に true 扱いになり、コンテキスト収集をスキップできない。
CI のドライラン設定で無効化したいユーザーがいるが、現状回避策が無い。

## ゴール
- `--context-only=false` を指定するとコンテキスト収集がスキップされる
- `--context-only` 単体指定（値省略）は従来通り true 扱い

## やらないこと
- 他の boolean フラグ（`--verbose` 等）の値解析ロジックの見直し

## 方針
`parseArgs` が boolean フラグを常に `true` に固定していたのが原因。
`--flag=value` 形式のときだけ値をパースするよう分岐を追加する。
フラグパーサー自体を汎用ライブラリに置き換える案もあったが、影響範囲が広く今回のバグ修正の範囲を超えるため見送り。

## 変更計画
1. `src/cli/parseArgs.ts` — boolean フラグに `=value` が付与されている場合は明示値を優先するよう分岐を追加
2. `src/cli/parseArgs.test.ts` — `--context-only=false` のケースを追加

## 検証
- [ ] `bun run test:run`
- [ ] `bun run cli --context-only=false` を手元で実行し、コンテキスト収集がスキップされることを確認

## リスク / ロールバック
既存の `--context-only`（値省略）の挙動に影響しないことをテストで担保する。
問題があれば `parseArgs.ts` の分岐追加分のみ revert すれば元に戻る。
```
