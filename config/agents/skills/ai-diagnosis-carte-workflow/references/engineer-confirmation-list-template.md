# エンジニア確認リスト テンプレート（フェーズ3）

エンジニアが**同じファイルに直接回答を書き込む**前提の記入式Markdown。営業さんはこのファイルをエンジニアに渡すだけ。

回答するのはPM（ミドル〜シニア）本人。回答者が最終責任者を兼ねるため、別途の承認欄は設けない。

## 出力ルール

- ファイル名: `エンジニア確認リスト_<顧客名>_<日付>.md`。チャットのダウンロードファイルとして出力する。
- **ファイル末尾に「AI用作業メモ」を必ず含める**。2回目チャットはこのメモだけを文脈として再開する。
- 各項目に「分類」「背景（なぜ聞くか）」「回答欄」を必ず付ける。
- 背景は1〜2行。カルテのどの判断に効くかを書くと、PMが的確に答えられる。
- 回答欄は `回答: （ここに記入してください）` の形にし、空欄と分かるようにする。
- 実現性・連携可否・セキュリティ・法務・データ整備・効果額の技術前提など**高リスク項目は必ず含める**。カルテの信用を左右する。
- 営業が答えられなかった項目は分類を `営業→PMへ転送` にして同じファイルに合流させる。

## 記入例

```markdown
## Q1. 反響簿・日報のデータはどこにどの形式で保存されているか？
- 分類: エンジニア確認
- 背景: AIで集約・二重入力削減を提案する前に、データが構造化されているか紙/画像かで実現難度が大きく変わるため。
- 回答: （ここに記入してください）

## Q2. 現行の顧客管理システムはAPI連携が可能か？
- 分類: エンジニア確認
- 背景: AX支援プランで自動連携を提案するか、手動運用に留めるかの判断に必要。連携不可なら効果額の前提が変わる。
- 回答: （ここに記入してください）
```

連携可否（Q2）はカルテの効果額前提を左右する高リスク項目。PMの回答が正典になるので、曖昧なら「要追加調査」と書いてもらい、カルテ側は断定を避ける。

## 回答取り込み時のチェック（フェーズ4）

- すべての `回答:` 欄が埋まっているか。空欄・「確認中」が残っていればカルテを作らず差し戻す。
- 回答が技術的にカルテの前提を覆す場合（例: 連携不可）、該当する診断項目の効果額・アプローチを見直す。
- 回答内容を相談ログに転記する。
